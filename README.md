# Электронное расписание — VK-бот и панель администратора

Бот для студентов: расписание пар, заметки, напоминания, дедлайны и пуши за
10 минут до начала пары. Плюс веб-панель, через которую администратор заливает
новое расписание из Excel и управляет пользователями.

Всё в проекте на русском — интерфейс, комментарии, коммиты. При правках
держитесь того же языка.

## Что запускается

| Процесс    | Команда                 | Что это                                                        |
|------------|-------------------------|----------------------------------------------------------------|
| `vk`       | `python -m vkbot`       | Основной бот (vkbottle, async). Он же `python vk_bot.py`.       |
| `web`      | `python web_panel.py`   | Панель на Flask + waitress. `--dev` поднимает dev-сервер.        |
| `telegram` | `python bot.py`         | **Легаси**, монолит на aiogram. Для запуска продукта не нужен.   |

## Быстрый старт

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt        # Windows: .venv\Scripts\pip

cp .env.example .env                             # и заполнить (см. ниже)
python -c "import secrets;print(secrets.token_hex(32))"   # → PANEL_SECRET

python web_panel.py                              # панель на http://127.0.0.1:5000
python -m vkbot                                  # бот, в отдельном терминале
```

Минимум, без которого не поднимется:

* `VK_TOKEN` — токен сообщества с правами «Сообщения». Без него бот не стартует.
* `ADMIN_ID` — ваш VK user_id. Это owner панели, единственный, кто может выдавать
  админку. Читается и ботом, и панелью — значение должно быть одно.
* `PANEL_SECRET` — секрет подписи сессий. Панель откажется стартовать без него.

Остальные переменные описаны в [.env.example](.env.example).

### Вход в панель

Пароля нет: в боте нажмите «🔑 Войти в панель» (или напишите `/login`) — придёт
одноразовый шестизначный код на 10 минут. Его вводите на `/login`.
Код одноразовый, выдача нового гасит предыдущий.

### Кто чем управляет

Ролей три: **владелец**, **админ** и обычный пользователь (видит только `/me`).

Владельцев два вида. Из `.env` — `ADMIN_ID`, а если нужно несколько, то
`ADMIN_VK_IDS=id1,id2`: их панель снять не может, только правка `.env` и рестарт.
Заведите здесь запасной аккаунт — иначе потеря доступа к вашему VK означает потерю
владения, и вернуть его сможет только тот, у кого есть доступ к серверу.

Второй вид выдаётся прямо в панели: «Управление админами» → «Передать владение».
Операция подтверждается одноразовым кодом из бота, попадает в аудит и уходит
уведомлением всем владельцам. Снятие владения оставляет человеку админку.
Ваше собственное владение из `.env` при этом неприкосновенно.

Полностью передать проект = выдать владение преемнику в панели и убрать себя из
`.env` на сервере. Второй шаг намеренно требует сервера: иначе перехваченная
сессия могла бы стереть последний якорь.

### Первое расписание

1. Панель → «Загрузить» → выбрать `.xlsx`.
2. Панель покажет дифф: сколько записей и направлений добавится и исчезнет.
   На этом шаге в базу ничего не пишется.
3. «Применить». Старая таблица уходит в `schedule_backup`, Excel сохраняется в
   `schedule_versions/`, бот подхватывает изменения в течение минуты.
4. Если расписания под рукой нет — сгенерируйте демо-файл в том же формате:
   `python tools/make_demo_schedule.py`

Откатиться на любую прошлую версию можно там же, в блоке истории загрузок.

## Проверки

```bash
pip install -r requirements-dev.txt
playwright install chromium          # один раз

pytest -q                            # 118 тестов, БД берётся временная

python web_panel.py &                # для сквозной проверки панель должна быть поднята
python tools/smoke_panel.py --shots shots/
```

```bash
ruff check .                         # линтер, тот же конфиг гоняет CI
```

Всё это же выполняется автоматически на каждый push — см.
[.github/workflows/ci.yml](.github/workflows/ci.yml).

`tools/smoke_panel.py` проходит реальным браузером весь путь администратора:
вход по одноразовому коду → дашборд → загрузка Excel → превью → применение →
расписание → аудит → выход. Возвращает код 1, если что-то на пути сломалось.

## Деплой

Готовые конфиги — в [deploy/](deploy/):

```bash
# на сервере, проект в /opt/vkbot
cp deploy/vkbot.service deploy/vkpanel.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now vkbot vkpanel
journalctl -u vkbot -u vkpanel -f

cp deploy/vkbot-backup.service deploy/vkbot-backup.timer /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now vkbot-backup.timer

cp deploy/nginx-panel.conf /etc/nginx/sites-available/vkpanel
ln -s /etc/nginx/sites-available/vkpanel /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d elschedule.ru
```

Бэкапы ставятся оттуда же: `vkbot-backup.service` и таймер к нему — ежедневно
в 04:30, хранение 14 дней, с проверкой целостности копий. Пути в юните указывают
на `/opt/vkbot` — при другом каталоге установки поправьте их перед копированием.

Два момента, которые легко упустить:

* **`PANEL_TRUSTED_PROXIES`.** За nginx — `1`, тогда панель берёт настоящий IP
  клиента для лимита попыток входа. Без nginx — строго `0`, иначе IP подделывается
  заголовком и лимит обходится.
* **Панель работает ровно в одном процессе.** Отложенные загрузки, прогресс
  рассылки и кэш `.ics` лежат в памяти процесса. Второй воркер сломает загрузку
  расписания. Масштабировать — только вынеся это состояние в БД.

Бэкап (обе базы + `schedule_versions/`, онлайн-копия, ротация 14 дней) делает
`deploy/backup.sh`, его запускает ежедневный таймер. Разово — `systemctl start
vkbot-backup.service`.

Живость проверяется через `/healthz`: `200` — все четыре воркера тикают,
`503` — какой-то встал (процесс при этом может быть жив, systemd такого не
заметит). Повесьте на этот URL внешний монитор.

Часовой пояс сервера должен быть `Europe/Moscow` — иначе журнал аудита разойдётся
с расписанием на три часа.

Чек-лист перед первым запуском — [docs/LAUNCH.md](docs/LAUNCH.md).

## Как устроено

Подробная карта кода — в [CLAUDE.md](CLAUDE.md). Коротко:

```
vkbot/                 основной бот
  config.py            env, пути БД, тайминги, MSK
  db.py                SQLite: схема, индексы, миграции (init() идемпотентен)
  state.py             персистентные состояния пошаговых диалогов
  handlers/            по домену; упорядоченный пайплайн, первый ответивший выигрывает
  models/              CRUD над SQLite, без ORM
  workers/             фоновые задачи: напоминания, дедлайны, пары, hot-reload
  schedule/            кэш направлений, чётность недели, импорт Excel
web_panel.py           панель одним файлом (роли: owner / admin / user)
import_excel.py        парсер расписания из Excel
tools/                 генератор демо-расписания, браузерная smoke-проверка
tests/                 pytest
deploy/                systemd + nginx
```

Две базы SQLite: `notes.db` (данные пользователей, сессии панели, аудит) и
`sсhedule.db` (расписание). В имени второй буква `с` — **кириллическая**, так
исторически на проде; не «исправляйте» её, путь берите из `config.SCHEDULE_DB`.
Обе можно перенести через `DATA_DIR` / `NOTES_DB` / `SCHEDULE_DB` в `.env`.
