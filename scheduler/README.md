# Прототип составителя расписания

Отвечает на вопрос «можно ли собирать расписание автоматически по заданным
критериям». Отвечает **на боевых данных вуза**, а не на игрушечном примере.

Это прототип и отдельная от бота вещь: ничего из `vkbot/` он не импортирует, в
рантайме не участвует, в `requirements.txt` не попадает.

## Запуск

```bash
pip install ortools
python -m scheduler --dump выгрузка.json
```

Выгрузка — это JSON-массив строк таблицы `schedule` (поля `course`,
`direction`, `day`, `time`, `subject`, `teacher`, `room`, `week`, `class_type`,
`date_range`). Снять с сервера:

```bash
sqlite3 -json /root/vkbot/s.db "SELECT course,direction,day,time,subject,teacher,room,week,class_type,date_range FROM schedule" > выгрузка.json
```

Полезные флаги: `--profiles баланс,студентам`, `-t 90` (секунд на подбор
времени), `--rooms-time-limit 30`.

## Что он делает

1. **Собирает вход из выгрузки** (`extract.py`). Текущее расписание — это
   допустимое решение задачи, которую мы решаем, поэтому из него
   восстанавливается почти весь вход.
2. **Расставляет занятия по времени** (`model.py`, фаза 1, CP-SAT).
3. **Раскладывает по аудиториям** (фаза 2), минимизируя перебежки между
   корпусами.
4. **Считает метрики** (`metrics.py`) и печатает их рядом с качеством текущего
   расписания.
5. **Проверяет результат независимым кодом** (`validate.py`) — солверу верим,
   но ошибка живёт не в нём, а в том, как мы задали модель.

## Почему вариантов несколько, а не один

Критерии конфликтуют. Чтобы уложить нагрузку преподавателя в три дня, кому-то
из групп придётся получить окна. Единственно верных весов не существует, это
вопрос политики вуза — поэтому считается несколько профилей (`profiles.py`) и
показывается таблица метрик. Выбирает человек.

## Что здесь синтетика

В базе лежит **результат** составления расписания, а не **вход**. Нет и
восстановить неоткуда:

- численность групп — сгенерирована детерминированно (14–30 человек);
- вместимость аудиторий — выведена из фактического спроса: комната обязана
  вмещать то, что в ней идёт сегодня;
- недоступность преподавателей — пустая; в жизни это главный источник
  переделок;
- часы дисциплин за семестр — заменены недельной повторяемостью из текущего
  расписания.

Всё это заменяется настоящими данными без переделки модели: меняется только
`extract.py`.

## Чего модель пока не умеет

- **Диапазоны дат** (`date_range`). Модель знает только чётность недели. В
  выгрузке таких строк шесть, но часть накладок в текущем расписании
  разведена именно датами.
- **Подгруппы.** Лабораторные обычно идут по половине группы; в выгрузке
  разметка подгрупп есть у шести строк, и она не разобрана.
- **Распределение нагрузки** — кто какую дисциплину читает. Это отдельная
  задача, которая решается до расписания.

## Побочный результат: аудит текущего расписания

Валидатор работает и на том расписании, которое действует сейчас, и находит в
нём накладки: одна аудитория на две группы, преподаватель в двух местах. Это
либо ошибки расписания, либо ошибки разбора Excel — и то, и другое стоит
посмотреть глазами.

## Проверки

```bash
pytest tests/test_scheduler.py -q
```

Отдельная работа в CI (`Прототип составителя расписания`) ставит ortools и
гоняет эти тесты; в основной матрице файл сам себя пропускает, потому что там
ortools не ставится.
